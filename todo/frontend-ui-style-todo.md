# 前端 UI 风格整体优化 TODO

目标：把当前 MVP 前端从“能跑的页面集合”提升为“清晰、稳定、适合仓储/转运日常操作的后台系统”。风格方向应偏安静、专业、可扫读，避免营销页式大卡片、强装饰渐变和过多视觉噪音。

## P0 - 先统一视觉地基

- [x] 建立统一设计基调
  - 关键词：物流后台、可靠、高效、低干扰、信息密度适中。
  - 主色建议从当前偏紫的 `--accent` 调整为更业务化的蓝/青绿色系，例如 `#2563eb` 或 `#0f766e`。
  - 保留少量强调色用于主操作、当前导航、关键状态，不让整站读起来像单一紫色主题。
  - 暗色模式继续保留，但先保证浅色模式体验，因为业务后台通常白天高频使用。

- [x] 重整全局设计 token
  - 在 `frontend/src/style.css` 中统一颜色、间距、圆角、阴影、字号、行高。
  - 卡片圆角建议保持 `8px` 左右，当前 `10px/12px` 可略收敛。
  - 阴影少用，只给浮层、菜单、移动端侧栏使用；普通业务区块优先用边框和背景层级。
  - 建议增加语义 token：`--success`、`--warning`、`--danger`、`--info`、`--muted`。

- [x] 统一字体层级
  - 页面标题统一使用 `.page-title`，不要在各页面混用 `title`、Tailwind 字号和内联样式。
  - 表格、表单、按钮字号建立标准：页面标题 22-24px，区块标题 15-16px，正文/表格 13-14px，辅助说明 12px。
  - 移除 `html` 在大屏自动放大到 17/18px 的规则；后台系统更需要稳定布局，不建议字号随大屏变大。

- [x] 清理混合写法
  - 当前页面同时使用全局 class、Tailwind utility、scoped CSS、内联 style，后续维护会越来越散。
  - 建议保留 Tailwind 做布局辅助，但把核心组件样式沉淀到全局类或共享组件。
  - 优先清理高频页面：`Orders.vue`、`Parcels.vue`、`OrderDetail.vue`、`Billing.vue`。

## P1 - 建立后台组件规范

- [x] 抽出基础布局组件
  - `PageHeader`：标题、说明、右侧主操作。
  - `FilterBar`：搜索、状态筛选、客户筛选、日期范围、刷新。
  - `DataTable` 或至少统一 `.table` 变体。
  - `EmptyState`：无数据、无搜索结果、接口异常。
  - `StatusBadge`：包裹、订单、任务状态统一展示。
  - 当前进度：已落地 `PageHeader`、`EmptyState`、`StatusBadge`，并统一了全局 `.table` / `.toolbar` 变体；`FilterBar` 尚未单独抽成组件。

- [x] 优化导航和应用外壳
  - 左侧导航增加图标，提升扫读速度。
  - 当前页面 active 状态可以更克制：左侧色条或浅底色即可，减少 outline 的突兀感。
  - 顶栏只保留高频信息：品牌、角色切换、暗色模式、折叠按钮。
  - 移动端侧栏打开时增加遮罩层，避免内容区域仍像可操作。

- [x] 统一按钮语义
  - 主按钮只用于当前页面最重要动作，例如“提交并通知”“开始打包”。
  - 次按钮用于查看、刷新、取消、下载。
  - 危险动作使用 `btn-danger`，并配确认弹窗。
  - 图标按钮用于折叠、关闭、刷新、下载等明确动作；可考虑引入 `lucide-vue-next`。

- [x] 统一表单体验
  - 输入框、select、日期时间字段统一高度、边框、焦点态。
  - 表单 label 不要只用 placeholder；关键业务字段需要固定 label，避免输入后上下文消失。
  - 必填、错误、禁用、loading 状态统一。
  - 弹窗表单底部按钮固定右对齐：取消在左，主操作在右。

## P1 - 重做关键页面信息架构

- [ ] 仪表盘改成运营概览
  - 当前 `Dashboard.vue` 是静态数据，建议改为角色化工作台。
  - customer：待到仓、可申请打包、待付款/待发货、最近订单。
  - staff：待审核包裹、待建单、待结算、异常订单。
  - operator：待打包任务、进行中任务、今日完成、异常备注。
  - 指标卡应小而密，重点数字突出，说明文字减少。

- [x] 包裹页强化批量工作流
  - 筛选区固定成一行/两行的工具条，减少页面跳动。
  - 状态用统一 badge，不直接显示普通文本。
  - 客户选择打包模式建议改成顶部批量操作栏，选中后固定显示。
  - 空列表、加载中、接口失败都要有明确状态。

- [x] 订单页改成真正的数据操作页
  - 标题从英文 `Orders` 统一为中文“订单”。
  - 分页占位“第 1-10 条，共 42 条”应改为真实数量，或在 MVP 中隐藏。
  - 操作列按钮过多时使用“查看”主入口 + 更多菜单，减少横向拥挤。
  - 金额、重量、状态、时间列要统一对齐和数字格式。

- [x] 订单详情页作为流程中枢
  - 详情页应突出当前状态、下一步动作、包裹清单、重量计价、收件信息。
  - 建议使用两栏布局：左侧主流程和表格，右侧订单摘要/费用/状态时间线。
  - 打包完成、通知客户、覆盖价格等高风险动作需要提示与确认。

- [x] 任务页从静态看板改为真实仓库任务台
  - 当前 `Tasks.vue` 还是静态示例，应接入 `/tasks`。
  - 三列看板可以保留，但卡片需显示订单号、客户、包裹数、开始时间、操作按钮。
  - 操作员视角要突出“开始处理”“完成并填写实际重量”。

- [x] 结算页去掉 SaaS 套餐卡
  - `Billing.vue` 的入门版/专业版/企业版不符合 TMS 业务后台。
  - 替换为待结算订单、计价规则、费用明细、人工覆盖记录。
  - 计价计算器可以保留，但应融入订单结算流程，而不是独立演示区。

## P2 - 状态、反馈与细节 polish

- [x] 建立状态色规范
  - 包裹：在途用 info，到仓用 success，申请打包用 warning，已打包用 neutral/success，拒绝用 danger。
  - 订单：草稿 neutral，待打包 info，打包中 warning，完成 success。
  - 任务：待办 neutral，进行中 warning/blue，完成 success。
  - 同一状态在所有页面必须颜色、文案、顺序一致。

- [x] 增加加载和错误反馈
  - API 请求时按钮进入 loading/disabled 状态。
  - 页面级 loading 用骨架或轻量占位，不要空白闪烁。
  - 请求失败使用统一 toast 或 inline alert，避免静默 catch。
  - 轮询刷新不要打断用户当前输入和选择。

- [x] 优化表格可用性
  - 长表格保留 sticky header，但需要确保深浅色背景正确。
  - 操作列可 sticky right，避免横向滚动后找不到按钮。
  - 移动端表格可改为列表卡片，但桌面端保持密集表格。
  - 数字列统一 `tabular-nums`，金额和重量右对齐。

- [x] 优化中文文案
  - 按钮文案使用动词 + 对象，例如“标记到仓”“提交通知”“覆盖价格”。
  - 避免中英混排占位：`actual_weight`、`rate_per_kg` 应改为“实际重量(kg)”“单价”“额外费用”。
  - 角色名、状态名、字段名保持同一套词表。

- [ ] 做响应式验收
  - 验收宽度：390px、768px、1280px、1440px。
  - 检查顶部栏、侧边栏、筛选区、弹窗、表格横向滚动。
  - 确保按钮文字不溢出、表单 label 不重叠、弹窗在小屏可滚动。

## 建议实施顺序

1. 统一 `style.css` token、按钮、输入框、表格、badge。
2. 抽 `StatusBadge`、`PageHeader`、`FilterBar`。
3. 先重做 `Orders.vue` 和 `Parcels.vue`，它们决定后台主观感。
4. 再做 `OrderDetail.vue`，把流程动作收束到详情页。
5. 替换 `Billing.vue` 的套餐卡，改成业务结算页。
6. 最后处理 `Dashboard.vue`、`Tasks.vue` 和移动端细节。

## 专家判断

这套 TMS 不需要“更炫”，需要更像一个每天会被员工反复打开的工作台。真正的高级感来自一致的信息密度、明确的主次动作、稳定的表格和表单、低噪音的状态反馈。先把设计系统和两三个核心页面打稳，整体质感会比单独换颜色或加阴影提升得更明显。
